# 🔷 仕組み：全体像、学習の流れ、手の選び方、候補の作り方、報酬

<a id="slide-2"></a>

## 価値ネットワークで手を選び、自己対戦の勝敗で鍛える

<sub>**全体像**</sub>

- **見る**：盤面をカードごとの数値の列と、盤面全体の数値に変換する
- **評価する**：**価値ネットワーク**が勝ちやすさ **V** を −1〜+1 で答える
- **学ぶ**：**自己対戦**の勝敗を答えにして V を修正する
- 手書きの評価式は使わない。手の良し悪しはすべて価値ネットワークの予測で決まる

> 📖 **用語メモ**
> - **価値ネットワーク**：局面を見て「このまま進むと勝てそうか」を数値で答えるニューラルネットワーク
> - **V**：その評価値。+1 に近いほど勝ち、−1 に近いほど負けを予想
> - **自己対戦**：同じ AI 同士で対局させ、その対局を教材にする方法

<details><summary>💬 補足</summary>

このデッキ全体の地図。左から右へ、盤面の読み取り、評価、学習の3段階。

</details>

## 1反復 = 対局 → 答え合わせ → 修正、5反復ごとに評価

<sub>**学習の流れ**</sub>

- **1 対局**：現行モデル同士で16局を並列に指す。**ε-greedy** でときどきランダムに指す
- **2 答え合わせ**：勝敗から各局面の目標値 **λ-return** を作る
- **3 修正**：**リプレイバッファ**から32局面ずつ取り出し、200回更新
- **4 評価**：5反復ごとに対戦して強くなったか判定

> 📖 **用語メモ**
> - **ε-greedy**：確率 ε でわざとランダムな手を指す工夫。同じ手ばかりだと新しい経験が増えないため
> - **λ-return**：最終的な勝敗と、次の局面での予測を混ぜた目標値。λ が大きいほど勝敗を重視
> - **リプレイバッファ**：その反復の局面と目標値をためる箱。無作為に取り出し、更新が終わったら空にする

<details><summary>💬 補足</summary>

1反復で16局（--games）を指し、そこで出てきた局面に目標値を付けて学習する。対局は CPU の数だけ同時に進める。ε は 0.15 から 0.03 へ徐々に下げる。深さ2以上で読むときは、目標値の「次の局面の予測」に対局中の探索値を使う。

</details>

<a id="slide-4"></a>

## 1手先読みで上位 k 手に絞り、N 手先まで読んだ値が最大の手を選ぶ

<sub>**手の選び方**</sub>

- **絞って読む**：候補手とステップ終了を仮に指して V で並べ、評価が高い順に **幅 k** 個だけを**ミニマックス**で N 手先まで読む。その中で最大の手を選ぶ。決着する手は勝ち +1 / 負け −1
- **候補を作る**：**Lv単位の列挙**で、メインステップの候補を平均 6.0 手にする（実測）
- **選ぶ余地がなければ進む**：**自動進行**：候補が1つだけなら評価せず指し、学習データにも入れない

> 📖 **用語メモ**
> - **ミニマックス**：自分の番では値が最大、相手の番では最小になる手を選ぶと仮定して先を読む方法
> - **Lv単位の列挙**：プレイはリザーブ払い、コアは「カードのLvを変える」「ソウルコアを動かす」で表す候補の作り方

<details><summary>💬 補足</summary>

深さ N は --depth（既定 1 = 1手先読み）、幅 k は --width（既定 1 = 最善の1手だけ深く読む、0 = 制限なし）。例：幅3・深さ2なら、1手先読みの上位3手だけを2手先まで読み直し、その中で最大の手を選ぶ（上位の外の手は選ばれない）。深さ1では全候補を評価するので幅は効かない。途中の局面でも、手番側にとって評価が高い順に k 手だけ展開する。評価対局では序盤4ターンだけ温度付きで選び、以降は値が最大の手を選ぶ。学習中の対局では ε の確率でランダムな手を選ぶ。

</details>

## コアは配置の全組み合わせではなく、Lv の変更として並べる

<sub>**候補の作り方**</sub>

| --actions | 中身 | 候補数（平均） |
|---|---|---|
| level（既定） | プレイはリザーブ払い・Lvの境目の配置。コアはカードの **Lv変更** と **ソウルコア移動**（各対象、プレイの間に1回） | 6.0 |
| all | 支払い・配置の全組み合わせと、コアの **一括再配置** | 1,223（場所5以下） |
| compact | 支払いは1通り、コア移動は意味のある組み替えだけ | 7.9 |

level でも、各カードの Lv（または消滅）とソウルコアの場所の組み合わせにはすべて届く。同じ対象を続けて動かさないので、コアを動かし続ける循環は起きない

- 一括再配置の数 = N × C(X+N−2, N−1)
- 86,632
- 場所7・コア12 のとき
- 930,240
- 場所8・コア15 のとき。終盤は全件を並べられない

> 📖 **用語メモ**
> - **Lv変更**：カードのコアを、そのLvにちょうど必要な数にする手。差分はリザーブとやりとりする
> - **一括再配置**：コアの最終的な置き方を1手で選ぶ手。N は場所の数（リザーブ＋カード）、X はコアの数

<details><summary>💬 補足</summary>

候補数の平均は selftest の実測（level・compact は144局面、all は場所5以下の130局面）。Lv の境目を超える余りのコアはリザーブに置く形にそろえる。カード効果が未実装の今のルールでは、カード上の余りとリザーブのコアは支払い・Lvアップ・破壊時の行き先のどれでも同じ扱いなので、結果は変わらない。all で学習するとメモリが 13GB を超え、実用にならなかった。

</details>

<a id="slide-6"></a>

## 選ぶときは V で比べ、終局後に勝敗で V を直す

<sub>**各選択肢の評価値**</sub>

- **対局中（手を選ぶとき）**：候補 A を指した後の局面
- V = +0.42 選択
- 候補 B を指した後の局面
- V = +0.18
- ステップ終了後の局面
- V = −0.05
- **終局後（学習するとき）**：実際に選んだ手の結果の局面だけを並べ、勝敗 z から逆向きに目標値 G を付ける
- 勝った局で選んだ手の V は上がり、負けた局の手の V は下がる
- 選ばなかった手には**教師信号**が届かない。その評価は**汎化**と ε によるランダムな手の経験に頼る

> 📖 **用語メモ**
> - **教師信号**：学習で「正解」として使う値。ここでは最終的な勝敗
> - **汎化**：学習した局面に似た、まだ見ていない局面でもうまく評価できること

<details><summary>💬 補足</summary>

評価値の数字（+0.42 など）は説明用の例で、実測値ではない。勝敗という1つの結果を、その局で選んだ各手へ配るのが目標値 G の役割。

</details>

<a id="slide-7"></a>

## 報酬は終局の結果だけ

<sub>**報酬と目標値**</sub>

- +1
- 勝ち
- −1
- 負け
- −0.1〜−0.9
- **手数上限引き分け**
- G[最後] = z（終局の報酬）
- G[t] = 0.3·V(s[t+1]) + 0.7·G[t+1] （λ = 0.7）
- 予測 V と目標値 G の**損失** 0.5·(V − G)² を小さくするよう重みを直す

> 📖 **用語メモ**
> - **手数上限引き分け**：決着しないまま手数上限（既定1500手）に達した対局。報酬 = −min(0.9, 0.1 + 0.8 × 引き分け率)。引き分けが多いほど強く罰する
> - **損失**：予測と目標値のずれの大きさ。小さいほど予測が正確。強さそのものではない

<details><summary>💬 補足</summary>

引き分け率は自己対戦1局ごとに更新する指数移動平均（係数 0.1）。引き分け率 0% なら −0.1、70% なら −0.66。途中の手には報酬がない。目標値 G は、そのプレイヤーが選んだ手の結果の局面を、終局から逆にたどって計算する。

</details>

# 🔷 価値ネットワーク：構成、GRU、規模、重みの直し方

<a id="slide-8"></a>

## カード列を GRU で要約し、盤面全体の数値と合わせて評価

<sub>**価値ネットワークの構成**</sub>

| 層 | 構成 | パラメータ数 |
|---|---|---|
| 埋め込み | カード番号 → 8個の数値（256枠 × 8） | 2,048 |
| 入力 | トークン 24個（能力値 16 + 埋め込み 8）× カード枚数、大域特徴 20個 | — |
| GRU | カード列を 32個の数値に要約 | 5,472 |
| 全結合 | (32 + 20) → 32、tanh | 1,696 |
| 出力 | 32 → 1、tanh で −1〜+1 | 33 |
| 合計 |  | 9,249 |

> 📖 **用語メモ**
> - **埋め込み**：カード番号を学習で決まる8個の数値に置き換えたもの。効果の違いを表す
> - **トークン**：カード1枚分の入力。場所・コスト・BP・Lv・コア数など16個と埋め込み8個
> - **大域特徴**：ライフ、リザーブ、手札の枚数、ターンなど、盤面全体を表す20個の数値
> - **全結合**：すべての入力とすべての出力を重み付きでつなぐ層

<details><summary>💬 補足</summary>

カード番号は効果と結び付くため、入力に必須。番号はハッシュで256個の枠に割り当てるので、新しいカードにもそのまま対応できる。入力は評価する側のプレイヤー視点で、相手の手札の中身と両者のデッキの中身は使わない。

</details>

## カード1枚を24個の数値で表し、盤面全体を20個で補う

<sub>**入力の詳細**</sub>

| カードの数値 | 内容 | 場／手札・トラッシュ |
|---|---|---|
| 所在・コスト（6） | 手札・自分の場・相手の場・自分と相手のトラッシュ、コスト ÷ 10 | どちらも |
| BP・Lv（2） | 現在の BP ÷ 10000、Lv ÷ 3 | 場のみ |
| コア・疲労（3） | コアの総数 ÷ 10、ソウルコアの有無、疲労していれば 1 | 場のみ |
| シンボル（2） | シンボル数 ÷ 3、軽減シンボル数 ÷ 3 | 場は前者、手札は両方 |
| 種別（3） | スピリット・ネクサス・その他 | どちらも |
| カード番号（8） | **埋め込み**：番号から決まる、学習される8個の数値 | どちらも |

- **盤面全体（20個）**：ライフ、リザーブとトラッシュのコア数、ソウルコアの有無、手札とデッキの枚数（相手の手札は枚数のみ）、場のシンボル数、ターン、手番、いまのステップ
- 入っていない：効果テキスト、系統、色の種類、アタック中のカード、コアの内訳

> 📖 **用語メモ**
> - **埋め込み**：カード番号を、学習で決まる8個の数値に置き換えたもの。効果の違いを表す
> - **one-hot**：選択肢のうち該当する1つだけを 1、ほかを 0 にする表し方

<details><summary>💬 補足</summary>

数値は 0〜1 程度に収まるよう、10 や 10000 などで割って規格化している。カードの並びは「相手トラッシュ → 自分トラッシュ → 相手の場 → 自分の場 → 手札」の固定順。非公開情報（相手の手札の中身、両者のデッキの中身）は使わない。実装は rl/src/Features.kt。

</details>

<a id="slide-10"></a>

## カードを1枚ずつ読み、覚え方を調整しながら要約する

<sub>**GRU の仕組み**</sub>

- カード 1
- カード 2
- …
- カード T
- 隠れ状態 h（32個の数値）
- z = σ(Wz·x + Uz·h + bz)
- r = σ(Wr·x + Ur·h + br)
- n = tanh(Wn·x + Un·(r⊙h) + bn)
- h′ = (1 − z)⊙h + z⊙n
- **更新ゲート z**：前の記憶を新しい内容にどれだけ書き換えるか
- **リセットゲート r**：新しい内容を作るとき、前の記憶をどれだけ参考にするか
- 読む順番で結果が変わるため、カードはいつも同じゾーン順で並べる

> 📖 **用語メモ**
> - **隠れ状態**：それまでに読んだカードの内容を要約した数値の組。1枚読むごとに更新される
> - **ゲート**：0〜1 の値をとる調整弁。σ（シグモイド関数）で 0〜1 に収める。⊙ は要素ごとの掛け算

<details><summary>💬 補足</summary>

GRU は RNN の一種。LSTM と比べてゲートが2つと少なく、軽い。入力 x はカード1枚分のトークン（能力値16個 + カード番号の埋め込み8個 = 24個）。パラメータは 3 × (32×24 + 32×32 + 32) = 5,472 個。

</details>

## パラメータ 9,249 個の小さなネットワーク

<sub>**ネットワークの規模**</sub>

- 9,249
- **パラメータ**の数（GRU 5,472 + 埋め込み 2,048 + 全結合 1,696 + 出力 33）
- 約 72KB
- 重みファイルの大きさ（1個 8バイト × 9,249）
- 5.4k × T
- 1局面の評価に必要な**積和**の回数（T = カード枚数）
- 幅を変えたときのパラメータ数（H = GRU、D = 全結合、E = 埋め込み次元、B = 枠数）
- 3·((16+E)H + H² + H) + (H+20)·D + 2D + 1 + B·E

H = D = 32、E = 8、B = 256 で 9,249 個（現在）。H = D = 64 なら 24,641 個

> 📖 **用語メモ**
> - **パラメータ**：学習で調整される数値（重み）。多いほど複雑な判断を表せるが、学習に時間がかかる
> - **積和**：掛け算して足し合わせる計算1回分。計算量の目安

<details><summary>💬 補足</summary>

計算量の大半は GRU で、カード1枚ごとに約5,400回の積和がかかる。埋め込みは表を引くだけなので計算量はほぼ増えない。幅（--hidden / --dense / --emb-dim / --emb-buckets）は新しく作るときだけ変えられる。埋め込みのない旧形式の重みは、読み込み時に埋め込みを追加して使える（評価値は変わらない）。

</details>

<a id="slide-12"></a>

## ずれを測り、さかのぼって原因を求め、少しずつ直す

<sub>**重みの直し方**</sub>

- **1 ずれを測る**：損失 0.5·(V − G)² を32局面分平均
- **2 原因を求める**：**BPTT** で各重みの**勾配**を計算
- **3 暴れを抑える**：**勾配ノルムクリップ**で大きさを 1.0 までに
- **4 直す**：**Adam** で重みを更新（学習率 0.001）

> 📖 **用語メモ**
> - **勾配**：重みを少し動かしたとき損失がどれだけ変わるか。重みを直す方向の手がかり
> - **BPTT**：GRU が読んだ順番を逆にたどって勾配を求める方法。最後のカードから最初へさかのぼる
> - **勾配ノルムクリップ**：勾配が大きすぎるときに縮める安全装置。1回の更新で重みが壊れるのを防ぐ
> - **Adam**：勾配の平均と大きさの履歴を見て、重みごとに動かす幅を自動で調整する更新方法

<details><summary>💬 補足</summary>

1回の更新で32局面を使い、1反復で200回更新する。BPTT は手書きで実装しており、セルフテストで数値微分と照合済み（相対誤差 1e-5）。

</details>

<a id="slide-13"></a>

## 独立した対局を、CPU の数だけ同時に指す

<sub>**並列化**</sub>

- **対象**：自己対戦・評価対局・リーグ戦・match・league の各局。**スレッド**数は --threads（既定は論理プロセッサ数）
- **安全に分ける**：ネットは読むだけ、エージェントは局ごとに複製、カードは先に読み込む。重みの更新は全局が終わってから
- **同じ結果**：乱数の種を局ごとに先に決めるので、スレッド数を変えても勝敗・手数は同じ（**再現性**を selftest で確認）
- 4.0秒 → 1.5秒
- 12局の対戦（Lv単位の列挙・深さ1）。1スレッドから6スレッドで約 2.7倍

> 📖 **用語メモ**
> - **スレッド**：1つのプログラムの中で同時に動く処理の流れ。CPU のコアごとに別の対局を進められる
> - **再現性**：同じ設定で動かせば、何度・どの環境でも同じ結果になること

<details><summary>💬 補足</summary>

Kotlin/Native の Worker を使う（rl/src/Parallel.kt）。計測環境は論理プロセッサ6個。学習の1反復（自己対戦32局＋5反復ごとの評価）は約1〜1.3分。

</details>

# 🔷 強さの判定：昇格条件、リーグと Elo

<a id="slide-14"></a>

## 2つの条件を両方満たしたときだけ最良を更新

<sub>**強くなったかの判定**</sub>

評価対局は5反復ごと。序盤4ターンは**温度**付き、以降は**貪欲**に指し、**先後交互**で対戦して**スコア**で比べる

- **条件 1 直接対戦**
- **今の最良に 20局で 55% 以上**：全局引き分けなら問わない
- かつ
- **条件 2 リーグ**
- **リーグで測った Elo が最良を上回る**：更新したモデルは**スナップショット**として保存し、リーグに加える

> 📖 **用語メモ**
> - **温度**：手の選び方のばらつき。0 なら最善手のみ
> - **貪欲**：評価が一番高い手だけを指すこと
> - **先後交互**：1局ごとに先手と後手を入れ替えること
> - **スコア**：勝ち1点・引き分け0.5点の平均。50% で互角
> - **スナップショット**：最良を更新した時点の重みを保存したもの

<details><summary>💬 補足</summary>

条件1は直前の最良との比較、条件2は歴代の相手全体との比較。両方を求めることで、特定の相手にだけ強いモデルの昇格を防ぐ。直接対戦が全局引き分けのときは判定材料がないため、条件2だけで判定する。序盤の温度は毎局同じ指し回しになって決着しないのを防ぐためで、比べる両者とリーグ全員に同じ設定を使う。

</details>


---

<a id="slide-15"></a>

## 歴代の最良モデル全員と戦い、強さを1つの数値にする

<sub>**リーグと Elo**</sub>

- ランダムに指す AI Elo 0（基準）
- 開始時点のモデル
- 歴代の最良 p1, p2, …
- 最大 8人
- 予想スコア = 1 / (1 + 10^(−差/400))
- Elo の差が 0 で 50%、+100 で約 64%、+200 で約 76%、+400 で約 91%
- 各メンバーと 10局ずつ対戦する
- メンバーの Elo は固定し、今のモデルの Elo だけを**最尤推定**で求める
- 全勝や全敗でも値が飛ばないよう、相手ごとに「0.5勝の仮想1局」を足す

> 📖 **用語メモ**
> - **Elo**：強さを表す数値。値そのものより差に意味があり、差から予想勝率が決まる
> - **最尤推定**：実際の対戦成績が一番起こりやすくなるように、未知の値を決める方法

<details><summary>💬 補足</summary>

リーグが8人を超えたら、ランダムに指す AI 以外で最も古いメンバーを外す。ランダムに指す AI に10局全勝したときの Elo は約529で、リーグが育つまでの実質的な上限になる。

</details>

# 🔷 パラメータとその存在意義

<a id="slide-16"></a>

## 経験の量・目標値・更新の強さを決める

<sub>**パラメータ 1/4 学習**</sub>

| パラメータ | 既定 | 存在意義 |
|---|---|---|
| --iters | 50 | 学習の総量。反復ごとに重みを保存し、評価の区切りにもなる |
| --games | 16 | 1反復で集める経験の量。多いほど目標値のばらつきが減るが、1反復が長くなる |
| --lambda | 0.7 | 目標値で終局結果と次局面の予測を混ぜる比率。1 に近いほど結果重視（ばらつき大）、0 に近いほど予測重視（偏り大） |
| --lr | 0.001 | 1回の更新で重みを動かす幅。大きいと不安定、小さいと学習が遅い |
| --updates | 200 | 1反復あたりの更新回数。集めた経験をどれだけ学習に使うか |
| --batch | 32 | 1回の更新に使うサンプル数。勾配のばらつきを抑える |
| --eps-start / --eps-end | 0.15 / 0.03 | 探索率 ε の始点と終点（線形に減らす）。序盤は多様な局面を経験し、終盤は本来の指し方に近づける |

<details><summary>💬 補足</summary>

いずれも valuerl train のオプション。ほかに --self-temp（既定 0）で自己対戦にも温度を使える（0 なら ε-greedy のみ）。--lambda はバイアスと分散のトレードオフ、--lr と --updates と --batch は更新の強さと安定性を決める。

</details>

<a id="slide-17"></a>

## 判定の頻度・精度・厳しさを決める

<sub>**パラメータ 2/4 評価**</sub>

| パラメータ | 既定 | 存在意義 |
|---|---|---|
| --eval-every | 5 | 評価の頻度。評価は対局数が多く重いため、間隔で計算量を調整する |
| --eval-games | 20 | 直接対戦の局数。多いほど判定の誤差が小さい（20局で標準誤差 約 ±11%） |
| --promote | 0.55 | 昇格に必要な直接対戦スコア。50% より高くして偶然の勝ち越しを弾く。全局引き分けなら問わない |
| --eval-temp | 0.05 | 評価対局の温度。毎局同じ指し回しになって決着しないのを防ぐ |
| --eval-temp-turns | 4 | 温度を使うターン数。序盤だけ散らし、それ以降は最善手で実力を測る |
| --league-games | 10 | リーグの各メンバーとの局数。Elo の推定精度を決める |
| --league-size | 8 | リーグの最大人数（ランダムに指す AI を含む）。多いほど偏りに強いが、評価が重くなる |
| --pool | なし | 既存の重みを開始時にリーグへ加え、学習の続きでも比較相手を引き継ぐ |

<details><summary>💬 補足</summary>

評価のコストは、直接対戦の局数 + リーグ人数 × リーグ局数 で決まる。既定ではリーグが満員のとき 1回の評価で最大 20 + 80 = 100局。

</details>

## 対局の打ち切り、モデルの大きさ、再現性

<sub>**パラメータ 3/4 対局・ネットワーク・実行**</sub>

| パラメータ | 既定 | 存在意義 |
|---|---|---|
| --max-steps | 1500 | 1局の手数上限。終わらない対局を打ち切る。デッキ切れで決着する前に切れないよう、1ターン約12手 × 約70ターンより大きくする |
| --draw-base / --draw-gain / --draw-max | 0.1 / 0.8 / 0.9 | 引き分けの報酬 = −min(max, base + gain × 引き分け率)。引き分けが多いほど引き延ばしを強く罰する |

| --emb-buckets / --emb-dim | 256 / 8 | カード番号の埋め込みの枠数と次元。枠が少ないと別のカードが同じ枠を共有する（新規作成時のみ） |

## 候補の作り方、読む深さと幅、同時に指す数

<sub>**パラメータ 4/4 候補・探索・並列**</sub>

| パラメータ | 既定 | 存在意義 |

| スコア | 勝ちを1点、引き分けを0.5点として局数で割った値。50% なら互角 |
| リーグ | 歴代の最良モデルとランダムに指す AI を集めた対戦相手の一覧 |
| Elo | 強さを表す数値。差から予想勝率が決まり、差 400 で約 91% |
| 最尤推定 | 実際の対戦成績が一番起こりやすくなるように、未知の値を決める方法 |
| スナップショット | 最良が更新された時点の重みを別ファイル（-p番号）に保存したもの |
| 埋め込み | カード番号を、学習で決まる8個の数値に置き換えて入力する方法。効果の違いを表す |
| 注意機構 | 入力どうしの関係の強さを計算し、重要なものほど強く反映させる仕組み |
| 方策 | 各候補手をどれくらいの確率で選ぶかを表すもの |
| MCTS | 有望な手を優先して何度も試し打ちし、その結果で手を選ぶ探索方法 |

## 探索・候補の作り方・並列化

<sub>**用語集 5/5**</sub>

| 用語 | 説明 |
|---|---|
| ミニマックス | 自分の番では値が最大、相手の番では最小になる手を選ぶと仮定して先を読む方法 |
| αβ枝刈り | ミニマックスで、結果に影響しないと分かった枝を読まずに省く工夫。答えは変わらない |
| 探索の幅 | 深く読む手を、1手先読みの評価が高い上位 k 手に限ること。速くなるが、上位の外の良い手は読み落とす |
| Lv変更 | カードのコアを、そのLvにちょうど必要な数にする手。プレイなどの間に各カード1回まで |
| 一括再配置 | コアの最終的な置き方を1手で選ぶ手。置き方の数が多すぎて終盤は全件を並べられない |
| 組み合わせ爆発 | 場所やコアが少し増えるだけで、組み合わせの数が急激に（掛け算で）増えること |
| スレッド | 1つのプログラムの中で同時に動く処理の流れ。CPU のコアごとに別の対局を進められる |
| 再現性 | 同じ設定で動かせば、何度・どの環境でも同じ結果になること |
| 有意 | 偶然では説明しにくいほど差が大きいこと。ここでは勝ち数と負け数の差が誤差の約2倍を超えること |
