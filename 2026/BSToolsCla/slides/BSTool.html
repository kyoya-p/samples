このデッキ全体の地図。左から右へ、盤面の読み取り、評価、学習の3段階。

学習の流れ

1反復 = 対局 → 答え合わせ → 修正、5反復ごとに評価

1　対局

現行モデル同士で16局を並列に指す。ε-greedy でときどきランダムに指す

2　答え合わせ

勝敗から各局面の目標値 λ-return を作る

3　修正

リプレイバッファから32局面ずつ取り出し、200回更新

4　評価

5反復ごとに対戦して強くなったか判定

用語メモ

ε-greedy：確率 ε でわざとランダムな手を指す工夫。同じ手ばかりだと新しい経験が増えないため

λ-return：最終的な勝敗と、次の局面での予測を混ぜた目標値。λ が大きいほど勝敗を重視

リプレイバッファ：その反復の局面と目標値をためる箱。無作為に取り出し、更新が終わったら空にする

発表者メモ

1反復で16局（--games）を指し、そこで出てきた局面に目標値を付けて学習する。対局は CPU の数だけ同時に進める。ε は 0.15 から 0.03 へ徐々に下げる。深さ2以上で読むときは、目標値の「次の局面の予測」に対局中の探索値を使う。

手の選び方

1手先読みで上位 k 手に絞り、N 手先まで読んだ値が最大の手を選ぶ

絞って読む

候補手とステップ終了を仮に指して V で並べ、評価が高い順に 幅 k 個だけをミニマックスで N 手先まで読む。その中で最大の手を選ぶ。決着する手は勝ち +1 / 負け −1

候補を作る

Lv単位の列挙で、メインステップの候補を平均 6.0 手にする（実測）

選ぶ余地がなければ進む

自動進行：候補が1つだけなら評価せず指し、学習データにも入れない

用語メモ

ミニマックス：自分の番では値が最大、相手の番では最小になる手を選ぶと仮定して先を読む方法

Lv単位の列挙：プレイはリザーブ払い、コアは「カードのLvを変える」「ソウルコアを動かす」で表す候補の作り方

発表者メモ

深さ N は --depth（既定 1 = 1手先読み）、幅 k は --width（既定 1 = 最善の1手だけ深く読む、0 = 制限なし）。例：幅3・深さ2なら、1手先読みの上位3手だけを2手先まで読み直し、その中で最大の手を選ぶ（上位の外の手は選ばれない）。深さ1では全候補を評価するので幅は効かない。途中の局面でも、手番側にとって評価が高い順に k 手だけ展開する。評価対局では序盤4ターンだけ温度付きで選び、以降は値が最大の手を選ぶ。学習中の対局では ε の確率でランダムな手を選ぶ。

Lv変更：カードのコアを、そのLvにちょうど必要な数にする手。差分はリザーブとやりとりする

一括再配置：コアの最終的な置き方を1手で選ぶ手。N は場所の数（リザーブ＋カード）、X はコアの数

各選択肢の評価値

選ぶときは V で比べ、終局後に勝敗で V を直す

対局中（手を選ぶとき）

候補 A を指した後の局面

V = +0.42　選択

候補 B を指した後の局面

V = +0.18

ステップ終了後の局面

V = −0.05

終局後（学習するとき）

実際に選んだ手の結果の局面だけを並べ、勝敗 z から逆向きに目標値 G を付ける

勝った局で選んだ手の V は上がり、負けた局の手の V は下がる

用語メモ

教師信号：学習で「正解」として使う値。ここでは最終的な勝敗

汎化：学習した局面に似た、まだ見ていない局面でもうまく評価できること

評価値の数字（+0.42 など）は説明用の例で、実測値ではない。勝敗という1つの結果を、その局で選んだ各手へ配るのが目標値 G の役割。

報酬と目標値

報酬は終局の結果だけ

+1

勝ち

−1

負け

−0.1〜−0.9

手数上限引き分け

G[最後] = z（終局の報酬）

G[t] = 0.3·V(s[t+1]) + 0.7·G[t+1]　（λ = 0.7）

予測 V と目標値 G の損失 0.5·(V − G)² を小さくするよう重みを直す

用語メモ

手数上限引き分け：決着しないまま手数上限（既定1500手）に達した対局。報酬 = −min(0.9, 0.1 + 0.8 × 引き分け率)。引き分けが多いほど強く罰する

損失：予測と目標値のずれの大きさ。小さいほど予測が正確。強さそのものではない

7 / 28
発表者メモ

引き分け率は自己対戦1局ごとに更新する指数移動平均（係数 0.1）。引き分け率 0% なら −0.1、70% なら −0.66。途中の手には報酬がない。目標値 G は、そのプレイヤーが選んだ手の結果の局面を、終局から逆にたどって計算する。

数値は 0〜1 程度に収まるよう、10 や 10000 などで割って規格化している。カードの並びは「相手トラッシュ → 自分トラッシュ → 相手の場 → 自分の場 → 手札」の固定順。非公開情報（相手の手札の中身、両者のデッキの中身）は使わない。実装は rl/src/Features.kt。

GRU は RNN の一種。LSTM と比べてゲートが2つと少なく、軽い。入力 x はカード1枚分のトークン（能力値16個 + カード番号の埋め込み8個 = 24個）。パラメータは 3 × (32×24 + 32×32 + 32) = 5,472 個。

ネットワークの規模

パラメータ 9,249 個の小さなネットワーク

9,249

パラメータの数（GRU 5,472 + 埋め込み 2,048 + 全結合 1,696 + 出力 33）

約 72KB

重みファイルの大きさ（1個 8バイト × 9,249）

5.4k × T

1局面の評価に必要な積和の回数（T = カード枚数）

幅を変えたときのパラメータ数（H = GRU、D = 全結合、E = 埋め込み次元、B = 枠数）

3·((16+E)H + H² + H) + (H+20)·D + 2D + 1 + B·E

H = D = 32、E = 8、B = 256 で 9,249 個（現在）。H = D = 64 なら 24,641 個

パラメータ：学習で調整される数値（重み）。多いほど複雑な判断を表せるが、学習に時間がかかる

積和：掛け算して足し合わせる計算1回分。計算量の目安

発表者メモ

計算量の大半は GRU で、カード1枚ごとに約5,400回の積和がかかる。埋め込みは表を引くだけなので計算量はほぼ増えない。幅（--hidden / --dense / --emb-dim / --emb-buckets）は新しく作るときだけ変えられる。埋め込みのない旧形式の重みは、読み込み時に埋め込みを追加して使える（評価値は変わらない）。

重みの直し方

ずれを測り、さかのぼって原因を求め、少しずつ直す

1　ずれを測る

損失 0.5·(V − G)² を32局面分平均

2　原因を求める

BPTT で各重みの勾配を計算

3　暴れを抑える

勾配ノルムクリップで大きさを 1.0 までに

4　直す

Adam で重みを更新（学習率 0.001）

用語メモ

勾配：重みを少し動かしたとき損失がどれだけ変わるか。重みを直す方向の手がかり

BPTT：GRU が読んだ順番を逆にたどって勾配を求める方法。最後のカードから最初へさかのぼる

勾配ノルムクリップ：勾配が大きすぎるときに縮める安全装置。1回の更新で重みが壊れるのを防ぐ

Adam：勾配の平均と大きさの履歴を見て、重みごとに動かす幅を自動で調整する更新方法

発表者メモ

条件1は直前の最良との比較、条件2は歴代の相手全体との比較。両方を求めることで、特定の相手にだけ強いモデルの昇格を防ぐ。直接対戦が全局引き分けのときは判定材料がないため、条件2だけで判定する。序盤の温度は毎局同じ指し回しになって決着しないのを防ぐためで、比べる両者とリーグ全員に同じ設定を使う。

リーグと Elo

ランダムに指す AI　Elo 0（基準）

開始時点のモデル

歴代の最良 p1, p2, …

最大 8人

予想スコア = 1 / (1 + 10^(−差/400))

Elo の差が 0 で 50%、+100 で約 64%、+200 で約 76%、+400 で約 91%

Elo：強さを表す数値。値そのものより差に意味があり、差から予想勝率が決まる

最尤推定：実際の対戦成績が一番起こりやすくなるように、未知の値を決める方法

パラメータ 1/4　学習

経験の量・目標値・更新の強さを決める

パラメータ既定存在意義
--iters50学習の総量。反復ごとに重みを保存し、評価の区切りにもなる
--games161反復で集める経験の量。多いほど目標値のばらつきが減るが、1反復が長くなる
--lambda0.7目標値で終局結果と次局面の予測を混ぜる比率。1 に近いほど結果重視（ばらつき大）、0 に近いほど予測重視（偏り大）

--updates2001反復あたりの更新回数。集めた経験をどれだけ学習に使うか
--batch321回の更新に使うサンプル数。勾配のばらつきを抑える
--eps-start / --eps-end0.15 / 0.03探索率 ε の始点と終点（線形に減らす）。序盤は多様な局面を経験し、終盤は本来の指し方に近づける
