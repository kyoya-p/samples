# Skill: BSTools Playmat & Rule Engine

このスキルは、Kotlin/Native (Amper) によるバトルスピリッツ（**スタンダード／エターナル両フォーマット**）の盤面シミュレーション・Playmats WebUI・常時接続SSEリアルタイム同期・**GodMode/PlayMode視点分離**・RuleAPI・GameServer連携・Playwrightテスト環境の運用と保守を行うための標準ガイドラインである。

ルール判定はすべて `model/src/Rules.kt` に集約し、GameServer と Playmats が同じ関数を共有する。
ルールに関わるコードには**必ず出典の条番号をコメントで残すこと**（下記「出典」参照）。

---

## 1. 複数クライアント間常時接続（SSE）リアルタイム同期仕様

ポーリングではなく、**Server-Sent Events (SSE: `GET /api/events`)** による常時接続・即時プッシュ同期を採用。

- **接続方式**: `new EventSource('/api/events')` (HTTP `text/event-stream` / ノンブロッキングソケット)
- **即時ブロードキャスト**:
  - いずれかのクライアント（Client A）が手札召喚・ステップ進行・コア移動・リセット等の操作を実行した瞬間、サーバー内の全常時接続クライアント（Client B, Client C...）へ最新の `GameState` JSON を即時プッシュ送信。
  - 受信側クライアントはゼロ遅延で盤面を自動再描画 (`render(data)`)。

## 2. 視点モード（GodMode / PlayMode）と公開・非公開情報

トップバーの「モード」セレクタ (`#viewer`) で視点を選ぶ。値は `?viewer=` クエリ or POST本文の
`"viewer"` としてサーバーへ送られ、`buildWebGameStateDto(state, viewer=…)` が視点ごとに
DTOをマスクして返す。**マスキングはサーバー側で行う**（クライアントに全データを送ってUIで隠すのではない）。
`/api/act` も同様にサーバー側で手番チェックする — UIのボタンを消すだけでは、直接APIを叩く不正操作を防げない。

| viewer | モード | 見えるもの | 操作できるもの |
|---|---|---|---|
| `0` | **GodMode** | 全情報（両者の手札・デッキ枚数など） | 両プレイヤーを操作できる |
| `1` / `2` | **PlayMode**（そのプレイヤー視点） | 公開情報 + 自分の非公開情報のみ | 自分が選択者 (`choosing_player`) のときだけ |

### 公開・非公開の区分（総合ルール 4-1 〜 4-9、Web調査で確認済み）

総合ルール 4-1-2「それぞれの領域にあるカードの**枚数**とコアの**数**はすべてのプレイヤーに公開されており、
いつでも確認することができます」。4-1-3 が公開領域/非公開領域を定義する。

| 領域 | 公開性 | 実装での扱い |
|---|---|---|
| 手札 | **非公開**（枚数のみ公開） (4-3-2/4-3-3) | 自分の手札は中身を返す。**相手の手札は GodMode でのみ中身を返し、PlayMode では `hand_count` だけ** |
| デッキ | **非公開**（残り枚数のみ公開）(4-2-2) | `WebPlayerDto` に中身のフィールドを持たせない。`deck_count` のみ。**所有者自身にも見せない**ので GodMode/PlayMode を問わずデッキの中身は送らない |
| トラッシュ | **公開**（カード・コアとも）(4-4-2) | `trash_cards` として両者の中身を**視点によらず**常に返す |
| フィールド / リザーブ / ライフ / ボイド | **公開** (4-5〜4-8) | 元から視点でマスクしていない |

**このゲームに「相手には見えるが自分には見えない情報」は存在しない**
（相手の手札以外はすべて自分にも見えるか、両者に見えないかのどちらか）。
新しく領域や情報を追加するときは、まずこの表のどこに属すか確認してから実装すること。

### 実装上の注意

- **盤面の向きが違う**: GodMode はターンプレイヤー基準（`state.activePlayer`）、PlayMode は
  常に指定プレイヤー基準（`state.player1`/`player2` 固定）で `player`/`opponent` を組み立てる。
  PlayModeでは視点を切り替えない限り自分の陣営が動かない。
- 選択肢 (`groups`) は **操作できない視点には渡さない**（見えると相手の手が読めてしまう）。
  UIは `can_act:false` のとき「⏳ プレイヤーNの選択を待っています」を表示する。
- SSE購読 (`/api/events?viewer=N`) は視点ごとに独立しており、`broadcastState()` は
  接続中の視点の集合だけDTOを1回ずつ作って使い回す（同じ視点の接続同士は同一ペイロード）。
- モードセレクタを変更したら **SSEを張り直してから** `/api/state` を再取得する
  （購読したままでは古い視点のデータが届き続ける）。

## 3. フォーマット（スタンダード / エターナル）

総合ルール 1-1-1: 「このゲームは、ブロックアイコンが英字のカードのみが使用できる『スタンダード』、すべてのカードが使用できる『エターナル』の2つの対戦フォーマットがあります。」

`GameFormat` (`model/src/Model.kt`) で区別する。**両者の違いはターンシークエンスと使用可能カードだけで、セットアップの数値と基本ルールは完全に同一**。

| | スタンダード | エターナル |
|---|---|---|
| ターン | **8ステップ**（第2メインあり） | **7ステップ**（第2メインなし） |
| 先攻1ターン目に無いステップ | コア・アタック・第2メイン | コア・アタック |
| 使用可能カード | ブロックアイコンが**英字**のもの<br>（2026/4/1〜2027/3/31 は「**A**」のみ） | **禁止カードを除く全カード** |
| 総合ルール | あり（Ver.1.0） | **なし**（ルールマニュアル Ver.17.1 のみ） |
| 固有機構 | — | ブレイヴ／アルティメット／煌臨／転醒／バースト／ミラージュ／契約カード／創界神 等 |

- **ドローステップは両フォーマットとも先攻1ターン目に例外がない**（飛ばすのはコアとアタック）。よくある誤りなので注意。
- エターナルでは5番目のステップは単に「メインステップ」。「第1メインステップ」という呼称は存在しない。
- 《真界放》《継召》等スタンダード発のカードもエターナルで使用可能（エターナルは上位集合）。

```
スタンダード: [スタート]→[コア]→[ドロー]→[リフレッシュ]→[メイン]→[アタック]→[第2メイン]→[エンド]
エターナル  : [スタート]→[コア]→[ドロー]→[リフレッシュ]→[メイン]→[アタック]→[エンド]
```

**ステップは順に進むだけで、「アタックを行わず次へ」のような分岐は存在しない。**
アタックしたくない場合はアタックステップで何も宣言せずに終了する。選択肢は常に「（現ステップ名）終了」のみ。

- 各ステップの処理:
  - `スタート`: デッキ0枚なら敗北判定 (7-2-2)
  - `コア`: ボイドからリザーブへコア1個 (7-3-2)
  - `ドロー`: 1枚ドロー (7-4-2)
  - `リフレッシュ`: トラッシュのコアをすべてリザーブへ戻し、自分のカードをすべて回復 (7-5-2)
- ステップ進行ボタンのラベルは現在のステップ名に追随させる。

## 4. 主要ルール（両フォーマット共通）

条番号はスタンダード総合ルール Ver.1.0。エターナルにも同内容がルールマニュアルで規定されている。

- **セットアップ** (6-1-1 / 6-2-1): デッキ40枚以上（上限なし）・同名3枚まで / ライフ5個・リザーブは通常コア3個+ソウルコア1個 / 初期手札4枚。
  （マリガン1回も規定されているが未実装）
- **カードの種別と扱い**: スピリットは「召喚」、ネクサスは「配置」、マジックは「**使用**」。
  **マジックはフィールドに置かれずコアも乗らない** (11-3-1-6: 使用中のマジックはどの領域にも属さない)。
  使用後はトラッシュへ送られる。マジックを召喚扱いにしてフィールドに残すのは明確な違反。
- **BP** (2-8-4): BPはLvごとに定義され、**Lvが変わればBPも変わる**。カードマスタの `lvInfo` は
  `"Lv,必要コア数,BP"` 形式なので3要素目をBPとして読むこと。固定値を持たせてはいけない。
- **コア移動**（メインステップの行動の1つ）: 自分の**リザーブとフィールドのカードの間でコアを自由に移動**できる。
  - **1度に2個以上まとめて移動できる**（1個ずつしか列挙しないのは不足）。
  - **ソウルコアと通常コアを交換できる**。総数が変わらないのでLvが維持され、
    「Lvを落とさずにソウルコアだけ回収する」という実用的な手になる。交換は逆向きの移動2件として表し、
    適用時は**先に両方から取り出してからまとめて置く**（途中で在庫不足にならないようにするため）。
  - 移動でLv1のLvコストを下回ったスピリットは消滅する。自壊と同様、列挙はするが評価値を下げる。
- **カウント**: **トラッシュとは別の「カウントエリア」に置かれたコアの数**。
  カウントに関する効果以外では移動・参照・**コストの支払いに使用できない**（公式Q&A）。
  ボイドから効果でのみ増えるため、効果未実装の現状では常に0が正しい。コア供給元に含めてはいけない。
- **コスト軽減** (2-3-3 / 11-1-1-4-1): 印刷された軽減シンボル1つを、自分のフィールドにある**同じ色のシンボル1つ**が打ち消す多重集合マッチ。
  軽減量は印刷された軽減シンボル数が上限。Lv0のスピリットはシンボルを持たない。軽減可能なら必ず軽減する（過剰払い禁止）。
  軽減はコスト支払いの**前**に確定するため、支払いで自分のシンボルが減ってもコストは変わらない (11-1-1 の手順順序)。
- **召喚** (11-1-1-5 / 11-1-1-6): 召喚コストのコアは**トラッシュ**へ移動し、カード上には**最低LvのLvコスト以上**のコアを置く。
  「以上」なので**最初からLv2・Lv3で召喚できる**。最低値しか列挙しないとこの合法手が選べなくなるので、
  各Lvのしきい値を配置枚数の候補にする (`placementOptions`)。
  ネクサスはLv1のLvコストが0のためコアを置かずに配置できる (3-3-3-3)。召喚酔いはない (3-2-4)。
- **コアの供給元** (11-1-1-5 / 11-1-1-6): 支払いも配置も「**フィールドまたはリザーブ**」のコアが使える。
  **ライフのコアは使えない**。ソウルコアは通常コアと同様に扱え、支払い・配置のどちらにも回せる。
  フィールドのカードからは**コアを全部抜いてもよい**。Lv1のLvコストを下回ったスピリットは消滅するが (3-2-5-4)、
  それも合法な手であり「コアをすべて取り除いて消滅させながら召喚」は公式Q&Aでも前提とされている。
  **自壊する手も列挙し、評価値を下げる**（1体あたり -0.30）。消滅したカードはトラッシュへ、残っていたコアはリザーブへ。
  WebUIでは R やスピリット上のコアをクリックして配分を指定し、一致する選択肢が実行される。
- **アタック / ブロック** (8-1): アタック宣言でそのスピリットを疲労させ、**ブロック宣言ステップへ進む**。
  - **ブロックを選ぶのはアタックされている側** (8-1-3-1)。ターンプレイヤーではないので、
    `GameState.choosingPlayerId` で選択者を切り替え、DTOの `choosing_player` で伝える。
    ブロック宣言中は「ステップ終了」を出さず、ブロックするかしないかを必ず選ばせる。
    **盤面の向きは入れ替えない**（下記「手番と選択者の表示」参照）。
  - ブロックは**任意・回復状態のスピリット1体のみ**・ブロッカーも疲労する。ネクサスはブロックできない。
  - ブロックあり: BP比較で低い方が破壊、**同値なら相打ち** (8-1-6-1)。**ライフは減らない**
    （ブロックしたスピリットがその後いなくなっても成立している）。
  - ブロックなし: 減るライフは**アタックしているスピリットのシンボル数** (8-1-5-1)、
    減ったライフのコアは**防御側のリザーブ**へ移る（トラッシュではない）。
  - 破壊されたスピリットの上のコアは持ち主の**リザーブ**へ戻る。
  - 解決後はアタック宣言ステップに戻り、回復状態のスピリットが残っていればもう一度アタックできる。
- **Lv** (2-8-3): `Lv = max{ n | カード上のコア数 >= Lvコスト(n) }`。コア数から常に再計算され、ラッチしない。
  カードマスタで Lvコスト0 のスピリットは《真界放》を表し、**ソウルコア**が乗っているときにそのLvへ到達する (12-2-1-1-2)。
  ネクサスの Lvコスト0 は Lv1 のことで消滅しない。
- **勝敗** (1-3-2): 相手のライフが0 / **相手のスタートステップに**相手のデッキが0枚。
  デッキ切れはドロー時ではなく次の自分のスタートステップで判定される。

### GameServer 連携

Playmats は**選択肢の列挙を GameServer に委譲する**（Readme の役割分担どおり）。
(旧称 BoardServer。ディレクトリ・モジュール名・変数名・CLIフラグ・APIフィールド名を GameServer に統一済み)

- Playmats が盤面を `POST /api/actions` (GameServer:8081) に送り、`List<GameAction>` を受け取る。
  デッキは列挙に不要かつJSONが肥大するため送らない。
- 盤面の保持と選択の適用は Playmats 側が行う。GameServer は状態を持たない純粋な列挙エンジンとして働く。
- **GameServerが落ちていても動作する**: 到達不能なら `model/src/Rules.kt` の同一関数でローカル列挙にフォールバックする。
  両者が同じ関数を使うため結果は完全に一致する。
- 落ちている間は10秒間リトライを間引き、UIが固まらないようにしている。接続状態は `GET /api/status` の
  `gameServerOnline` で確認できる。接続先は `--game-url` または `POST /api/config`（JSONキーは `gameServerUrl`）で変更可能。
- GameServer 自身のデモ局面の列挙は `GET /api/actions`（旧 `AvailableAction`/`GET /api/legacy-actions` は削除済み）。

## 5. 局面ハッシュによる繰り返しの検出

**同じ局面に戻るだけの手も、ルール上は合法な手であり選択を妨げない。**
「選ぶと局面が進まない」ことは AI の自動選択を惑わせる情報だが、プレイヤー自身が
（例えば時間稼ぎ・様子見のため）あえて選ぶことは規則上できるため、**選択肢からは外さない**。
その代わり、選ぶと既訪問の局面に戻ることを GameAction/UI の両方で必ず明記する。

`positionHash()` がステップ・ターン・手番・フォーマット・勝者・アタック中のカードIDと、
両プレイヤーのライフ／リザーブ／トラッシュ／デッキ枚数／手札／フィールド
（カードNo・コア数・疲労状態）を畳み込む。到達した局面は `GameState.visitedPositions` に記録し、
列挙時に各選択肢を `snapshot()` 上で試し、結果が既出なら
**`eval=0.0` に上書きしたうえで `repeatsPosition=true` を付ける（`forbidden` にはしない）**。
`forbidden`/`forbiddenReason` は真に選択不可能な手のために予約し、現状このコードベースでは
一切セットしていない。

| フィールド | 意味 | 選択できるか |
|---|---|---|
| `forbidden` / `forbidden_reason` | 真に選択不可能な手（現状未使用、将来のため予約） | 不可。`disabled` にする |
| `repeats_position` | 選ぶと既訪問の局面に戻る（盤面が進まない） | **可能**。選ばせた上で明記する |

UI側 (`optionStatusPrefix`/`optionStatusTitle`, `index.html`) は両方の状態を区別して表示する。

```
🚫[理由]  ...      ← forbidden: ボタンをdisabledにし、クリックしても実行できない
🔁[同一局面] ...    ← repeats_position: 選択可能。波線の下線で明記し、クリックすれば実際に実行される
```

**なぜ評価値だけを下げ、選択は妨げないのか**: 当初はハードブロック（forbidden）で実装したが、
「ルール上合法な手をUIが勝手に禁止するのはおかしい」という指摘を受けて現行仕様に改めた。
評価値0だけで十分にAIの自動選択（評価値最大を選ぶ戦略）は往復を避ける
（コア移動は A➔B でBのLvが、B➔A でAのLvが上がるため、どちらも「Lvが上がる手」として
高評価になり往復が止まらなかったが、実際に繰り返しと判定された側の評価値を0にすれば、
ステップ終了などの他の手のほうが必ず高評価になり自動選択は先に進む。60手規模の自動プレイで
無限ループしないことを確認済み）。

実装上の注意:

- **ハッシュには `deck` の実体ではなく `deckCount` を使う**。GameServer へ送る局面はデッキを外すので、
  実体を見ると送信側と受信側でハッシュが食い違い、判定が常に不成立になる（実際に踏んだ）。
- 手札とフィールドは並び順に意味がないので**ソートして正規化**してから畳み込む。
- ステップ進行 (`END_STEP`) は必ず局面を進めるので判定をスキップする。
- 消滅を伴う移動などは総数が変わるため別局面になり、正しく選択可能なまま残る。

## 6. WebUI の表示規約

### 選択肢のアイコン

選択肢は「さらに分岐するもの」と「クリックで即実行される最終選択肢」が混在するため、**必ず見分けが付くようにする**。

| アイコン | 意味 |
|---|---|
| `▶` / `▼` | クリックすると**下の階層が開く**（閉／開）。件数は「(Nパターン)」で併記 |
| `⏎` | **最終選択肢。クリックすると即実行される** |

- 選択肢が1つしかないグループ／サブグループは、意味のない階層を挟まず**見出しクリックで直接実行**し `⏎` を出す。
- 評価値バッジ（勝率%）は全階層に出し、最良手は緑で強調する。

### 階層構造

```
🎴【召喚】 カード名  ▶            ← グループ（コスト軽減後の姿）
  └ コスト2, 配置コア:1 (4パターン) ▶   ← 必要コアの選び方
      └ ⏎ (支払:R:1, フラッティ:1, 配置:R:1)   ← コアの供給元。ここが最終選択肢
```

### コストとコアはアイコンで表記する

選択肢の中のコスト・コア数は、盤面と同じ **🔷(通常コア) / 🔶(ソウルコア)** で表す（`coreIcons()`）。
数字を読まなくても必要量が一目で分かる。

```
コスト🔷🔷🔷, 配置コア🔶, (支払:R:🔷🔷🔷, 配置:R:🔶)
🔷🔷を移動      🔶 ⇄ 🔷 を交換      通ればライフ-🔷
```

手札カードをクリックしても同じ階層が開く。R やスピリット上のコアを直接クリックして配分を組み立てると、
一致する最終選択肢が自動で選ばれる（`updateCoreAllocationUI`）。
そのため**選択肢の `detail` 末尾の括弧内は機械可読な書式を崩さないこと**
（`parseDetailSources` が解析する）。消滅などの注記は**括弧の外**に置く。

> ⚠️ **正規表現の文字クラスに絵文字を入れないこと。** `u` フラグなしの `[💲📥]` は
> 上位サロゲート `\uD83D` を含み、同じ `\uD83D` で始まる **🔷(U+1F537)/🔶(U+1F536) まで壊す**。
> 実際にこれでコア数が全て0に数えられ、配分が一致しなくなった。
> 選択肢の並び `(?:支払|配置|💲)` として書き、`u` フラグを付けること。

### 見出しの階層

パネル内には2種類の見出しがあり、**役割が違うので見た目を分ける**。

| | 用途 | スタイル |
|---|---|---|
| `<h2>` (`#my-title` / `#opp-title`) | パネル全体の見出し（自分／相手） | アクセント色 + **下線**（区切り線） |
| `<h3 class="zone-label">` | 領域ラベル（フィールド／手札） | 小さめ・弱色・**下線なし**・左に細いバー |

領域ラベルに `.panel h2` の下線が付くと、**線が「上のブロックの締め」に見えてラベルが直下のカードから
切り離される**。ラベルは中身の上に詰めて（margin-bottom 4px 程度）ひとかたまりに見せること。
緑枠の強調もパネル見出しに限定し、領域ラベルまで染めない。

**ステップ終了ボタンは「自分」パネルの見出し行 (`.side-head`) に置く。**
盤面の向きを固定した結果「自分 = 常にターンプレイヤー」であり、ステップを終了するのも常に
ターンプレイヤーなので一致する。ただし**選択者が相手に移る局面（ブロック宣言）や決着後は
`n_index` が null になるので、ボタンは無効化ではなく非表示にする**
（相手宛ての指示ラベルが自分側に残って見えるため）。

### 手番と選択者の表示

`player` / `opponent` は**常にターンプレイヤー基準で固定**し、盤面の上下を入れ替えない。
ブロック宣言のように選択者が相手に移る局面では、**緑枠（`.active-turn`）を相手パネルへ移し**、
タイトルに `⬅ 選択中` を付けて示す。

```
自分（プレイヤー2・手番）              ← 枠なし
相手（プレイヤー1） ⬅ 選択中           ← 緑枠。この人が選ぶ番
```

盤面を入れ替えると「今どちらの陣営を見ているのか」が分からなくなるため、
**視点は動かさず、どちらが選ぶ番かだけを示す**こと。判定には DTO の `choosing_player` を使う
（`active_player` は手番プレイヤーのままなので混同しない）。

### 選択肢ホバー時のコア移動プレビュー

選択肢にマウスを乗せると、そのプレイで**動くコアの場所**を盤面上にマークする。

| 表示 | 意味 |
|---|---|
| 橙の実線 + `N🔷` | そこからコアが出る（移動元・支払い元） |
| 緑の実線 + `N🔷` | そこへコアが入る（移動先） |
| 黄の破線 + 両方のバッジ | 出入り両方がある（ソウルコアと通常コアの交換） |

**バッジは個数だけを出し、`+`/`−` の記号は付けない**（方向は枠の色で示す）。
クリックでコアを選んだときのバッジ・配分バーも同様に個数のみ。

判定に必要な情報は**サーバーが `core_effects` として構造化して渡す**（`source_id` / `label` / `normal` /
`soul` / `direction`）。`detail` 文字列のパースに頼らないこと。
召喚・マジック使用は支払い分と配置分を合算して1件の `from` にまとめる。

- `source_id` は `"Reserve"` またはフィールドカードの `instanceId`。
  WebUI は `#my-reserve-box` と `#my-field .card[data-obj-id=...]` を引き当てる。
- バッジは `.core-fx-badges` コンテナに横並びで入れる。交換では同じ場所に2つ付くため、絶対配置で重ねない。
- `render()` でも必ずクリアする（カード画像プレビューと同じ理由）。

### カード画像プレビュー

ホバーで拡大画像を出す。**`render()` は手札・フィールドを `innerHTML=""` で作り直すため、
ホバー中の要素がDOMから消えても `mouseleave` は発火しない**。
これを放置するとプレビューが消え残るので、以下の3重で防いでいる。

1. `previewOwner` に表示元の要素を保持し、`render()` の先頭で `hideCardPreview()`
2. 画像の遅延ロード完了時に `previewOwner === el && el.isConnected` を確認してから表示
3. `document` の `mouseover` で、owner が切り離された／範囲外に出たら隠す

## 8. ビルド & 実行コマンド

**`index.html` はサーバー起動時に一度だけ読み込まれる**（`loadHtmlFile()`）。
HTML/JS/CSS だけを直した場合もビルドは不要だが、**Playmats の再起動が必要**。
再起動を忘れるとブラウザをリロードしても古い画面のままで、修正が効いていないように見える。

```shell
# 全モジュールビルド
.\amper.bat build

# GameServer (ポート 8081) 起動
.\amper.bat run -m GameServer

# Playmats (ポート 8080) 起動 (SSE常時接続・GameServer連携)
.\amper.bat run -m Playmats -- --game-url http://localhost:8081
```

## 9. Playwright 自動テスト手順

```shell
# 単体UI・操作シナリオテスト
node test_playmats.js

# 複数クライアント間SSEリアルタイム同期テスト
node test_multi_clients.js

# GodMode/PlayModeの情報マスキング・操作権限テスト
node test_viewer_modes.js

# ゲームを決着まで自動プレイする通しテスト
node test_full_game.js
```

`test_viewer_modes.js` は GodMode 1枚 + PlayMode(P1/P2) 2枚のタブを開き、
相手の手札が PlayMode で隠れる／トラッシュは PlayMode でも見える／手番でない視点は
`can_act:false` になる／**`/api/act` を直接叩いても手番チェックで拒否される**（UI側の非表示に頼っていないか）
を検証する。

`test_full_game.js` は GodMode視点のまま「評価値が最大の手を選ぶ」AIで**両プレイヤーの手番を決着まで自動進行**させ、
以下を検証する（下記「AI自動プレイによる検証」の選択則をそのままPlaywrightテスト化したもの）。
- 手数上限(500)以内に `winner` が1か2で確定すること（局面が同一局面往復などで進まなくなる回帰の検出）
- 複数ターンにわたって進行していること（`distinctTurns >= 2`）
- 決着後は `groups` が空になり `n_index` が `null` になり、勝者バナーが表示されること

**盤面はサーバー側で共有される単一の状態**なので、各テストは必ず先頭で新規ゲームを開始すること。
前のテストが残した局面に依存すると、実行順によって落ちる（実際に踏んだ）。
選択肢を `doAct(1)` のように index 決め打ちで選ぶのも禁止。列挙順が変わると別のカードを引く。
カード種別で選び（`/【召喚】|【配置】/` など）、`forbidden` を除外すること。
`repeats_position` は選択できてしまう（意図的にそう作ってある）ので、直前の手を打ち消すような
コア移動を誤って選ばないよう、決定的なテストではカード種別で明示的に絞り込むこと。

### AI自動プレイによる検証

ルールの穴は、局面を最後まで自動で進めると出てくる。ブラウザで以下を流し、
決着するか・手順がルールどおりかを確認する。

```js
// 評価値が最大の選択肢を選び、ステップ終了より低ければステップを進める。
// 同一局面に戻る手(repeats_position)は選択自体は可能だが eval=-1.0 に下げてあるので、
// 「評価値最大」で選ぶ限り自然に避けられる。forbidden は真に選択不可な手用（現状未使用）。
let best = null;
for (const g of current.groups) for (const o of g.options) {
  if (o.forbidden) continue;
  if (!best || o.eval > best.eval) best = o;
}
await doAct(best && best.eval > current.n_eval ? best.index : current.n_index);
```

- **1回の `orca eval` に長い自動プレイを入れない**。応答待ちでランタイム接続が切れる。15手程度ずつ分割する
  （`test_full_game.js` のように Playwright の `page.evaluate` 内で完結させる場合はこの制約を受けない）。
- 決着後は `groups` が空・`n_index` が `null` になることも確認する。
